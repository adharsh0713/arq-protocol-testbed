# Benchmarks and Research Answers

**Status:** Provisional smoke evidence only. The full 905-attempt repeated-trial matrix has not been executed in this release candidate. No RQ1–RQ6 performance hypothesis is confirmed or refuted.

## 1. Evidence boundary

The committed CSV was generated by:

```bash
python -m experiments.runner --tier smoke --workers 1 --overwrite
```

Environment at capture: Python 3.13, Linux container, localhost UDP, 4,096-byte chunks, 50 ms timeout, 15 retransmissions maximum, and one worker. Each smoke configuration was run once. `small.txt` is 8 KiB. The smoke tier applies equal configured loss to DATA and ACK directions at 0% and 20%; all six runs completed and passed byte-count and SHA-256 verification.

**This sample is a pipeline/correctness check, not a comparative benchmark.** It is too small to support statistical claims, and it does not exercise delay, corruption, duplication, reordering, timeout sensitivity, or combined faults.

## 4. Required final matrix

Run the pre-registered full matrix from the repository root:

```bash
python -m experiments.runner --tier full --workers 1
python -m experiments.analysis
```

The matrix is frozen at 905 attempted transfers:

| Matrix | RQ | Attempts |
|---|---|---:|
| DATA/ACK loss sweep | RQ1 | 200 |
| Delay × window sweep | RQ2 | 140 |
| Reordering sweep | RQ3 | 200 |
| Corruption sweep | RQ4 | 100 |
| Duplication sweep | RQ4 | 100 |
| Timeout sensitivity | RQ5 | 90 |
| Combined faults across all five fixtures | RQ6 | 75 |
| **Total** |  | **905** |

Five trials are used for standard characterization points and ten for headline loss/reordering points. The runner assigns deterministic seeds from base seed `20261113` and matrix order, stores every attempted outcome, and derives performance plots from verified successes only. Failures remain in success-rate denominators.

## 5. Reproducibility and interpretation

- Input data: `data/test_files/` plus `manifest.json`.
- Raw attempt records: `data/results/experiment_results.csv`.
- Aggregates: `data/results/aggregated_results.csv`.
- Configured/realized fault comparison: `data/results/fault_rate_comparison.csv`.
- Figures: `docs/graphs/`; `plots_manifest.json` names the generated outputs and source CSV.
- Full process-level logs and metrics are under `data/results/runs/` during/after execution; they are not included in the clean source ZIP by default.

A final RQ answer must report sample count, success rate, median, Q1, Q3 and IQR for successful verified trials, configured and realized faults, and relevant failure categories. It must be labelled **confirmed**, **refuted**, or **inconclusive** only after inspecting the complete matrix. Do not convert missing data or failed-run throughput to zero.
